## When to use it

- Use a button to trigger actions, events, or main workflows (such as submitting forms, confirming choices, or proceeding to the next step).
- Buttons should be easy to locate, scan, and understand as actionable items.
- Buttons can serve as entry points into deeper workflows, dialogs, or page transitions.
- Buttons can be placed together in a row or grouped logically (such as primary and secondary actions in a footer).
- Labels should clearly describe the action the button performs, optionally accompanied by leading or trailing icons for added context.
- Buttons come in different variants (such as filled or outlined) and interactive states (default, hover, focus, disabled) to clearly communicate availability and interactivity.

### When not to use it

- Don't use buttons for navigation links that take users to a different website or page content (use text links or navigational tabs instead). **Use instead:** text links or navigational tabs.
- Don't crowd too many high-priority buttons together; avoid having multiple primary buttons side-by-side in the same view.
- Don't use buttons as static informational tags or badges where no action is performed.
- Don't rely on icons alone inside a button without an accessible text label or tooltip, unless the icon's meaning is universally understood.

## Best practice

- Adjust button placement and hierarchy so the primary call-to-action remains the main focus on the screen.
- When designing forms or dialogs, consistently align primary actions (e.g., "Save" or "Submit") and secondary actions (e.g., "Cancel") following platform conventions.
- Use distinct styles (such as fill vs. outline) to distinguish between primary and secondary actions.
- Ensure buttons provide clear visual feedback across all states (hover, focus, active, and disabled).
- Keep button text concise and action-oriented, typically starting with a strong verb.
- Ensure touch targets on mobile devices are large enough to be easily tapped (minimum recommended size).
- Support keyboard navigation with clear focus rings around buttons.
- Maintain consistent spacing around buttons to prevent accidental clicks, especially on dense layouts or mobile screens.

## Accessibility

- Renders a native &lt;button&gt; element, so Enter and Space activate it and it is in the tab order. ([`src/components/Button/Button.tsx:62`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L62))
- type defaults to "button", so it does not submit a surrounding form unless type="submit" is passed. ([`src/components/Button/Button.tsx:55`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L55))
- The disabled prop or state="disabled" sets the native disabled attribute, which removes it from the tab order and blocks clicks. ([`src/components/Button/Button.tsx:60`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L60))
- Remaining props, including aria-\* attributes, are spread onto the &lt;button&gt;. ([`src/components/Button/Button.tsx:63`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L63))
- The accessible name is the label text from children (default "Button"), rendered in a &lt;span&gt;. ([`src/components/Button/Button.tsx:71`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L71))
- Leading and trailing icons are Material Symbols ligatures in a &lt;span&gt; with aria-hidden="true", so they are not announced. ([`src/components/Button/Button.tsx:40`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L40))
- Keyboard focus (:focus-visible) removes the browser outline and shows focus only as a background colour (fill) or border colour (outline) change. ([`src/components/Button/Button.css:93`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.css#L93))
- There is no loading or pressed state and no aria-busy or aria-pressed handling. ([`src/components/Button/Button.tsx:8`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L8))

## Props

### Button

| Prop | Type | Default | Description |
|---|---|---|---|
| `state` | `ButtonState` | `'default'` | Figma `state`. Pins a look for documentation and testing. Real pointer hover, keyboard focus (`:focus-visible`) and the native `disabled` attribute apply the same looks on their own, so leave this at `default` in product code. `disabled` here also disables the button natively. |
| `shape` | `ButtonShape` | `'fill'` | Figma `shape`: `fill` (primary background) or `outline` (stroked, transparent background). |
| `showLeadingIcon` | `boolean` | `true` | Figma `showLeadingIcon`. Shows the icon before the label. Figma default: true. |
| `showTrailingIcon` | `boolean` | `true` | Figma `showTrailingIcon`. Shows the icon after the label. Figma default: true. |
| `leadingIcon` | `string` | `'add'` | Code only (Figma has no instance-swap property for it): Material Symbols name of the leading icon. Default `add`, the Material equivalent of Figma's "+" glyph. |
| `trailingIcon` | `string` | `'add'` | Code only, as `leadingIcon`: Material Symbols name of the trailing icon. Default `add`. |
| `children` | `ReactNode` | `'Button'` | The label. Figma models it as the text layer "Button", not as a component property. |

Also takes every native `<button>` attribute (`onClick`, `type`, `disabled`, `aria-*`, …). Source: [`src/components/Button/Button.tsx`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Button/Button.tsx#L11).

| Component | Empty field(s) | Missing source |

| Button | `variant_intent.*.purpose` (state, shape, showLeadingIcon, showTrailingIcon) | The Usage frame (315:1428) names the variants only collectively ("Buttons come in different variants (such as filled or outlined) and interactive states (default, hover, focus, disabled)…"; Best Practice: "Use distinct styles (such as fill vs. outline) to distinguish between primary and secondary actions."). It never says which value is for what, so no per-value purpose was transposed. A designer should state what `fill` and `outline` (and each state, and the icon toggles) are for. |

From the build report [`docs/button-build-report.md`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/docs/button-build-report.md):

| # | What | Figma | What the code does |
|---|---|---|---|
| G1 | Height | fixed 42, no token | derived from bound tokens: line-height 24 + 2 × `spacing/sm` + 2 × `borderWidth/sm` = 42. Fill carries a transparent stroke so both shapes match |
| G2 | Icon size | **Resolved 2026-11-20.** Figma's LeadingIcon/TrailingIcon hold a Material Symbols Rounded `add` glyph: font size bound to `fontSize/xl`, line height to `lineHeight/sm`, padding `spacing/none` | `--fontsize-xl` and `--lineheight-sm`. `lineheight-sm` is 24px in Burmese, so the glyph sits about 2px low there (owner's choice) |
| G3 | Icon colour tokens | icon strokes bound to `color/border/brand/light`, `color/border/inverse`, `color/border/primary` | used exactly as bound. Design may want the `color/icon/*` family instead |
| G4 | Icon stroke weight | **Resolved 2026-11-20.** The Figma vector was replaced by the Material Symbols glyph, so there's no separate stroke weight | Material Symbols `add` at its default weight, same as Figma |
| G5 | Pressed and loading states | not in the component set | not styled. No `loading` prop |
| G6 | Icon glyph swap | no instance-swap property; always "+" | `leadingIcon` / `trailingIcon` props (code only, default `add`) so consumers can pick a Material Symbol |
