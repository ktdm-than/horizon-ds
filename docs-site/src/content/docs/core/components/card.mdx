## When to use it

- Use a card to display content and actions on a single topic.
- Cards should be easy to scan for relevant and actionable information.
- Cards can serve as entry points into deeper levels of detail or navigation, such as a music album or details on an upcoming vacation.
- Cards can be displayed together in a grid, vertical list, or carousel.
- Use cards to contain related elements
- Contents can include anything from images to headlines, supporting text, buttons, and lists
- Can also contain other components in slot area.
- Cards have flexible layouts and dimensions based on their contents. Configuration is done at subcomponent level: CardLayout.

### Where it goes

<Aside type="caution" title="Where it goes: no story places it">
No story at `d1860fe` renders Card inside another component, so the intent file's `placement` is empty.
</Aside>
### When not to use it

- Don’t scroll within a card to reveal information
- Cards shouldn’t contain content that can be swiped, such as an image carousel or pagination. Also, swipe gestures shouldn’t cause portions of cards to detach upon swiping.
- Don’t let cards bump other elements out of the way. When a card is picked up, it appears in front of all elements, except app bars and navigation.
- On a mobile device, cards can't internally scroll, as it could cause two scroll bars to be displayed.

## Best practice

- Adjust the card layout so content remains the main focus on large screens
- When designing for large screens, use multiple columns to display content
- Certain devices or user contexts require different components to meet platform expectations
- Expand a card to reveal information
- A card should only have one swipe action assigned to it
- When moving a card, increase its elevation
- On a mobile device, cards can expand to reveal more content, scrolling within the screen. Content within cards doesn’t scroll.

## Accessibility

### Card

- Renders a plain &lt;div&gt; wrapper with no role, landmark or accessible name. ([`src/components/Card/Card.tsx:29`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/Card.tsx#L29))
- Card takes no onClick, href or keyboard handler; it is not interactive itself. ([`src/components/Card/Card.tsx:15`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/Card.tsx#L15))
- Card always renders CardContainer with state="hover", so its elevation is always on and does not signal focus or hover. ([`src/components/Card/Card.tsx:30`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/Card.tsx#L30))

### CardContainer

- Renders two nested &lt;div&gt;s (container and containerSlot) with no role or accessible name. ([`src/components/Card/CardContainer.tsx:14`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardContainer.tsx#L14))
- The hover elevation is applied by state="hover" or pointer :hover only; there is no :focus-within equivalent for keyboard users. ([`src/components/Card/CardContainer.css:12`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardContainer.css#L12))

### CardImage

- alt defaults to "", so the &lt;img&gt; (rendered only when src is set) is treated as decorative unless alt is passed. ([`src/components/Card/CardImage.tsx:18`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardImage.tsx#L18))
- Without src no &lt;img&gt; is rendered; only the placeholder background shows. ([`src/components/Card/CardImage.tsx:21`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardImage.tsx#L21))
- The hover overlay &lt;div&gt; has aria-hidden="true". ([`src/components/Card/CardImage.tsx:22`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardImage.tsx#L22))
- The overlaid IconBtn receives the iconBtn props (e.g. onClick, aria-label) and CardImage's state; CardImage sets no accessible name for it. ([`src/components/Card/CardImage.tsx:23`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardImage.tsx#L23))

### CardLayout

- Renders &lt;div&gt;s only (layout, CardData column and ContentSlot) with no role; reading order is CardImage, then CardText, then the ContentSlot, in both orientations. ([`src/components/Card/CardLayout.tsx:26`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardLayout.tsx#L26))
- CardImage is always rendered at ratio 1:1; the ratio cannot be changed from CardLayout. ([`src/components/Card/CardLayout.tsx:27`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardLayout.tsx#L27))

### CardText

- The title is rendered as a &lt;p&gt;, not a heading element, so it does not appear in a screen reader's heading list. ([`src/components/Card/CardText.tsx:34`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardText.tsx#L34))
- Subtitle, rating, review count, price and unit are each rendered as a separate &lt;p&gt;. ([`src/components/Card/CardText.tsx:35`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardText.tsx#L35))
- showReview and showPrice render only while showMetadata is true. ([`src/components/Card/CardText.tsx:37`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardText.tsx#L37))
- The rating is plain text (e.g. "4.7") with no accessible label naming it as a rating. ([`src/components/Card/CardText.tsx:41`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/src/components/Card/CardText.tsx#L41))

### The parts

#### CardContainer

Base structural frame for card components that manages outer surface styling, elevation (shadows), borders, padding, and corner radius. <small>(Figma component description)</small>

<Aside type="caution" title="CardContainer: no usage in Figma">
CardContainer's block on the Figma page carries no usage text, so its `use_when`, `dont_use_when` and `best_practice` are empty.
</Aside>
#### CardImage

Media subcomponent for cards that manages image display ratios, gradient overlays for contrast, and overlaid action buttons (e.g., favorite heart trigger). <small>(Figma component description)</small>

<Aside type="caution" title="CardImage: no usage in Figma">
CardImage's block on the Figma page carries no usage text, so its `use_when`, `dont_use_when` and `best_practice` are empty.
</Aside>
#### CardLayout

Structural layout container used to switch between horizontal (row) and vertical (column) arrangements for card components. <small>(Figma component description)</small>

<Aside type="caution" title="CardLayout: no usage in Figma">
CardLayout's block on the Figma page carries no usage text, so its `use_when`, `dont_use_when` and `best_practice` are empty.
</Aside>
#### CardText

Text metadata subcomponent for cards that standardizes typographic hierarchy, including title, subtitle, location, review rating, and pricing details. <small>(Figma component description)</small>

<Aside type="caution" title="CardText: no usage in Figma">
CardText's block on the Figma page carries no usage text, so its `use_when`, `dont_use_when` and `best_practice` are empty.
</Aside>
## What this version promises

The package is `0.1.0` in `package.json` at `d1860fe`. From [`VERSIONING.md`](https://github.com/ktdm-than/horizon-ds/blob/d1860feaaa47e0af02a0d0b0f0ac52cba9a7aca2/VERSIONING.md):

The package is `0.x`. While it is:

- **Minor** (`0.1.0` → `0.2.0`) for any addition, and for any change that would be major after
  1.0.0. A breaking change in a minor bump is listed under Changed or Removed in the changelog,
  with what to change in consumer code.
- **Patch** (`0.2.0` → `0.2.1`) only for fixes, as defined above.

Going to **1.0.0** is a human decision, not one a release run makes.

This component's props, its exported types, the semantic tokens it uses and the stylesheet entry points are the public API that promise covers. Class names inside the markup (`hds-*`) are not.

export function Listing() {

      </Button>

  );
}
